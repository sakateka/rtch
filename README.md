# rtch

[English](README.en.md)

Менеджер терминальных сессий на Rust для Linux. Supervisor обслуживает PTY
дочернего процесса; клиенты подключаются через Unix-сокет. Отключение клиента
или SSH-соединения не завершает процесс. Живой вывод передаётся без фильтрации;
picker восстанавливает экран терминала в памяти.

## Сборка и установка

Требуется stable Rust 1.88 или новее.

```sh
cargo build --release --locked
install -Dm755 target/release/rtch ~/.local/bin/rtch
```

Каталог `~/.local/bin` должен входить в `PATH`.

## CLI

```text
rtch [OPTIONS]
rtch [OPTIONS] SESSION [PROGRAM [ARGS...]]
rtch [OPTIONS] COMMAND [COMMAND_OPTIONS] [SESSION] [PROGRAM [ARGS...]]
```

Без `PROGRAM` запускается `$SHELL` (или `/bin/sh`) как login-shell.
Bash читает `~/.profile`, если его не перекрывают `~/.bash_profile` или `~/.bash_login`.
Явные программы сохраняют правила запуска; переподключение не перечитывает профиль.
Опции rtch указываются до `PROGRAM`; последующие аргументы передаются программе.

```sh
rtch new monitor htop
# Detach: Ctrl+\
rtch attach monitor

rtch new dev bash -l
rtch start build make
rtch tail -f build
```

| Команда | Действие |
| --- | --- |
| `rtch` / `rtch pick` | Список сессий с предпросмотром Beginning/Ending |
| `rtch shell-init` | POSIX-хук для выбора сессии при входе в shell |
| `rtch SESSION` | Подключение к активной сессии или создание отсутствующей |
| `rtch new SESSION [PROGRAM...]` | Создание с подключением; явный перезапуск ended/stale |
| `rtch start SESSION [PROGRAM...]` | Создание без подключения |
| `rtch run SESSION [PROGRAM...]` | Supervisor на переднем плане; возврат кода завершения программы |
| `rtch attach SESSION` | Подключение к активной сессии |
| `rtch detach SESSION` | Отключение всех клиентов без завершения программы |
| `rtch list` / `ended` | Все сессии / только ended |
| `rtch tail [-f] [-n LINES] SESSION` | Чтение истории; `-f` — отслеживание новых данных |
| `rtch push SESSION` | Передача stdin во вход сессии |
| `rtch clear [SESSION]` | Очистка лога и буфера истории; без имени — текущая сессия |
| `rtch kill [-f] SESSION` | SIGTERM, затем SIGKILL через 5 с; `-f` — сразу SIGKILL |
| `rtch rm SESSION` / `rm -a` | Удаление одной / всех ended/stale сессий вместе с историей |
| `rtch current` | Имя текущей сессии или цепочка вложенных сессий |

`Ctrl+\` отключает текущий клиент. Если приложение перехватывает сочетание,
`rtch detach monitor` выполняется из другого терминала. Содержимое экрана
после отключения может сохраниться. Выход из дочернего процесса завершает сессию.

## Выбор сессии и login-хук

`rtch` без аргументов и `rtch pick` показывают все состояния сессий, начиная
с последней активности; при равенстве используется имя. При обычном размере
терминала видны восемь строк списка, остальные доступны прокруткой.
Beginning начинается с первой сохранённой строки, Ending — с последних.
Выбор другой сессии сбрасывает вертикальную и горизонтальную прокрутку обоих предпросмотров. Ограниченный виртуальный
экран vt100 применяет перемещения курсора, стирание,
Backspace и перерисовки; OSC/DCS и опасные управляющие символы не отображаются.
Ratatui рисует панели; строки объединяются в логические только по маркерам
мягкого переноса vt100. Переносы перед широкими символами без такого маркера
могут сохраняться. Длинные строки обрезаются внутри панели, а горизонтальная прокрутка
показывает сохранённый текст за её краем. Графемы не разрезаются;
частично видимые широкие символы заменяются пробелами.
Отсутствующий, пустой или небезопасный лог заменяется сообщением.
Виртуальный экран использует размер вызывающего терминала и до 1024 строк
scrollback. Исторические размеры не записаны, поэтому после изменения размера
или ротации реконструкция полноэкранной истории приблизительна.
Без TTY выводится подсказка команд без raw-режима.

- `Tab` / `Shift+Tab`: переключение List → Beginning → Ending; активный
  предпросмотр расширяется.
- Вверх/вниз, `k`/`л` (вверх), `j`/`о` (вниз), `PageUp`/`PageDown`, `Home`/`End`: перемещение
  или прокрутка логических строк активной панели.
- Влево/вправо, `h`/`р` (влево) или `l`/`д` (вправо): горизонтальная прокрутка активного предпросмотра
  по колонкам. Beginning и Ending сохраняют отдельные смещения; в списке эти клавиши ничего не делают.
- `Enter`: подключение к работающей отсоединённой сессии или перезапуск ended/stale
  под тем же именем с сохранением истории в пределах настроенного лимита лога.
  Занятая attached-сессия оставляет picker открытым.
  Перезапуск запускает текущий `$SHELL` как новый login-shell в вызывающем
  каталоге; исходная программа или процесс не возобновляются.
- `Insert` (также `n`/`т`): редактирование предложенного свободного имени, затем `Enter` создаёт
  сессию с подключением. Стрелки, `Home`/`End`, Backspace и Delete редактируют
  имя по границам графем; `Insert` и `F2` при вводе имени ничего не делают.
  Латинские и русские буквы команд вводятся буквально, кроме
  настроенной печатной клавиши detach: её исходный символ по-прежнему завершает picker.
  `Esc` отменяет ввод имени. Максимум — 107 байт;
  перевод строки при вставке не подтверждает имя.
- `Ctrl+Shift+K`: немедленная принудительная остановка выбранной running/attached-сессии через SIGKILL,
  включая foreground- и background-задания её Unix-сессии. Подключённые клиенты отключаются;
  история сохраняется, та же строка становится ended. Picker остаётся открытым;
  затем Delete удаляет остановленную сессию. Это работает и с супервизорами,
  запущенными до обновления picker. Процессы, покинувшие исходную Unix-сессию через `setsid`,
  не входят в эту очистку.
- `Delete` (также `d`/`в`): удаление выбранной ended/stale-сессии и её файлов с выбором соседней сессии.
  Работающие сессии, включая attached, удалять нельзя.
- `F2` (также `c`/`с`): очистка сохранённых логов и буфера live-истории с сохранением сессии,
  процесса и подключённых клиентов. Новый вывод продолжает записываться
  в пределах настроенного лимита. Удаление и очистка обновляют предпросмотры и оставляют picker открытым.
- `q`/`й`, `Esc`, `Ctrl+C`, `Ctrl+D` или настроенная клавиша detach: возврат в вызывающий shell.

Стрелки, `Tab`/`Shift+Tab`, `Enter`, `Escape`, `Insert`, `Delete` и `F2` обеспечивают
навигацию, открытие, создание, удаление и очистку в любой раскладке.
Принудительная остановка требует терминала, который различает Ctrl и Shift
через протокол клавиатуры kitty/CSI-u или xterm modifyOtherKeys. Используйте
`Ctrl+Shift+K` в английской QWERTY или `Ctrl+Shift+Л` на той же физической
клавише в стандартной русской ЙЦУКЕН. В старых терминалах, передающих один байт
для `Ctrl+K` и `Ctrl+Shift+K`, это сочетание недоступно; остаётся команда
`rtch kill -f SESSION`. Имя вводится без преобразования символов.
Bracketed paste не активирует буквы команд picker или действия функциональных клавиш. `Ctrl+C`, `Ctrl+D` и настроенная
управляющая клавиша detach по-прежнему завершают picker при вставке. После открытия сессии буквы команд
и байты навигационных клавиш, `Insert`, `Delete` и `F2` передаются приложению без изменений,
кроме настроенного байта detach, если отсоединение включено.

В маленьком терминале отображается предложение увеличить окно; принудительная остановка, удаление и очистка
доступны только при полном отображении picker. Если каталог сессий занят,
повторите действие после освобождения. Если имя
не помещается на экране, создание недоступно до изменения размера.
Выход, ошибка и обрабатываемые сигналы завершения восстанавливают
настройки терминала и предыдущий экран.

Внутри сессии rtch (непустой `RTCH_SESSION`) запуск picker, создание сессии
и подключение к другой сессии запрещены до изменения терминала или сессии.
Команды управления, включая `list`, `current`, `tail`, `clear`, `push`,
`detach` и `kill`, остаются доступны.

Для автоматического запуска picker в интерактивном login-shell сохраните
резервную копию стартового файла и добавьте вывод `rtch shell-init` после
настройки PATH:

```sh
rtch shell-init >> ~/.profile
```

Используйте файл, который читает ваш shell: в Bash `.bash_profile` или
`.bash_login` имеют приоритет над `.profile`. POSIX-хук запускает дочерний
процесс, поэтому выход из picker и detach возвращают в исходный shell.
Хук пропускает неинтерактивные shell и запуск без TTY, дочерние shell rtch
(`RTCH_SESSION`), `RTCH_BYPASS=1`, `TERM=dumb` и отсутствующий исполняемый файл.
Ошибка picker не прерывает запуск shell, включая профиль с `set -e`.
Для одного входа без picker: `RTCH_BYPASS=1 bash -l`.

## Состояния сессии

| Состояние | Значение |
| --- | --- |
| `running` | Supervisor работает, подключённых клиентов нет |
| `attached` | Есть подключённые клиенты |
| `ended` | Сессия завершена; сохранены состояние и/или лог |
| `stale` | Сокет остался, обслуживающий процесс отсутствует |

Завершённые сессии перезапускаются через `Enter` в picker или явно через
`rtch new work`. Именованные `rtch work` и `attach` не перезапускают их автоматически.
Picker запускает текущий login-shell в вызывающем каталоге. История доступна
через `tail`; `rtch rm work` удаляет завершённую сессию, `rtch rm -a` —
все ended/stale, сохраняя живые. Состояние и код завершения хранятся
в `.ended` даже без логирования; оставшийся без процесса сокет — `[stale]`.

Обновлённый supervisor атомарно отклоняет подключение из picker, если уже есть
подключённый клиент. Для старого supervisor picker ждёт ответ о возможностях
ограниченное время и перепроверяет состояние сокета перед обычным подключением.
Этот совместимый путь не гарантирует единственного подключения, если другой
клиент подключается одновременно.

После перезагрузки ОС сохраняются файлы, но не процессы.
Полная справка: `rtch --help`, `rtch COMMAND --help`.

## Конфигурация и хранение

Каталог сессий по умолчанию — `~/.cache/rtch/`.
Пример подготовки отдельного каталога:

```sh
mkdir -p ~/.config/rtch /mnt/data/rtch
chmod 700 /mnt/data/rtch
```

Файл `~/.config/rtch/config`:

```ini
session_dir = /mnt/data/rtch
quiet = false
log_size = 8m
detach_key = ^\
suspend = true
ansi = true
redraw = winch
clear_mode = none
tail_lines = 10
tail_follow = false
```

Приоритет: CLI → конфиг → defaults. Значения выше соответствуют defaults,
кроме примера `session_dir`.

| Ключ | CLI | Значения |
| --- | --- | --- |
| `session_dir` | Абсолютный `SESSION` | Абсолютный путь без кавычек |
| `quiet` | `-q` | `true/false`, подавление сообщений о состоянии |
| `log_size` | `-C SIZE` | Сжатые байты, суффиксы `k/m`; по умолчанию `8m`; `0` отключает лог; минимум положительного значения — `256` байт, максимум `256m` |
| `detach_key` | `-e KEY`, `-E` | Один байт, `^X`; `none` отключает клавишу |
| `suspend` | `-z` отключает | `true/false`, локальная обработка Ctrl+Z |
| `ansi` | `-t` отключает | `true/false`, ANSI-сброс терминала при отключении |
| `redraw` | `-r MODE` | `none/winch/ctrl_l` |
| `clear_mode` | `-R MODE` | `none/move` |
| `tail_lines` | `tail -n LINES` | Неотрицательное целое |
| `tail_follow` | `tail -f` | `true/false` |

Булевы опции допускают явное переопределение: `--quiet=false`, `--no-detach=false`,
`--no-suspend=false`, `--no-ansi=false`, `tail --follow=false`.
Ошибки и неизвестные ключи в конфиге отклоняются. `force`, `all`, имя сессии
и запускаемая команда в конфиг не входят.

Путь абсолютный, без кавычек; пробелы разрешены, `~` и переменные не
подставляются. Пустые строки и комментарии с `#` игнорируются.
При абсолютном `XDG_CONFIG_HOME` конфиг находится в `$XDG_CONFIG_HOME/rtch/config`.

Каталог должен принадлежать текущему UID и запрещать запись группе и остальным.
Абсолютный путь вместо имени переопределяет каталог, но не остальные настройки;
`list` и `rm -a` используют
настроенный каталог. Суффиксы `.log`/`.ended`/`.head`, двоеточия и управляющие символы
в именах зарезервированы.

## Bash-дополнение

Текущий shell:

```bash
source <(COMPLETE=bash rtch)
```

Автозагрузка при подключённом `bash-completion`:

```bash
completion_dir="${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions"
mkdir -p "$completion_dir"
COMPLETE=bash rtch > "$completion_dir/rtch"
```

Tab дополняет команды, опции, значения `-r`/`-R`, программы и сессии
(включая имена с пробелами). Для `attach/detach/push/kill` — живые,
для `rm` — ended/stale, для `tail/clear` и создания — все.
Список обновляется на каждом Tab.

## История и ограничения

История по умолчанию ограничена 8 MiB после сжатия на сессию. Суммарный размер
основных файлов `.log` и `.head`, включая служебные данные, не превышает лимит.
Оба файла содержат независимые кадры zstd уровня 1 с контрольными суммами,
заголовком версии/поколения rtch и трейлерами длины/порядкового номера. Кадр
распаковывается максимум в 128 KiB; каждый read из PTY (до 8 KiB) сразу
публикуется. Ротация удаляет старейшие целые кадры конца истории пакетами через
атомарную замену файла. Временная сжатая копия не входит в лимит и удаляется
после замены. Повторное открытие супервизором и удаление сессии убирают
оставшиеся временные копии; работающий писатель удерживает эксклюзивную блокировку.

`-C 4m` меняет лимит сжатых данных; положительные значения меньше 256 байт
отклоняются, максимум — 256 MiB. `-C 0` оставляет только 128 KiB истории в памяти
и файл состояния, без постоянной истории. Буфер повторного показа независимо
ограничен заданным числом байт (128 KiB при отключённом логе). Приватный `.head`
сохраняет непрерывное начало до 64 KiB после распаковки, занимая не более половины
сжатого бюджета. Если часть начала не помещается, захват прекращается до `clear`
и не продолжается после пропуска. При малых лимитах слишком большие записи
конца сокращаются до помещающейся последней части. Beginning эмулирует до 64 KiB
этого префикса, Ending — до 128 KiB последнего вывода с ограниченным контекстом;
начальная неполная строка пропускается. Предпросмотр распаковывает нужные кадры,
а `tail` расширяет окно только при нехватке запрошенных строк, максимум до 256 MiB.
`tail -f` учитывает замену файла, ротацию, очистку и перезапуск без повторного
вывода уже прочитанных сохранённых записей. Незавершённая последняя запись ждёт
дописывания; при открытии супервизором она отбрасывается. Повреждённая завершённая
запись вызывает ошибку.

Beginning останавливает эмуляцию до вытеснения первых строк
из ограниченного scrollback. Восстановленные строки экрана и scrollback
доступны прокрутке. `clear` очищает обе истории, `rm` удаляет обе.
Старые текстовые логи читаются без изменения, включая вывод работающих старых
супервизоров. В сжатый формат их преобразует только новый супервизор при
повторном открытии, после проверки обоих файлов. Для старых сессий без `.head`
Beginning показывает начало сохранившегося лога;
утраченные данные восстановить невозможно. Если начало управляющей строки
утрачено при ротации или находится вне ограниченного окна чтения, оставшийся
текст может быть неоднозначным. Полные распознанные строки и отдельные
завершители обрабатываются консервативно. При отключённом логе предпросмотра
с диска нет, кроме истории, оставшейся от предыдущего запуска.
При повторном показе фильтруются запросы терминалу и
неподдерживаемые управляющие последовательности; живой вывод не меняется.

При отсоединении и `SIGHUP` восстанавливаются настройки терминала;
`SIGKILL` обработать невозможно. До 64 подключений; клиенты с переполненными
очередями отключаются. Логи могут содержать секреты: приватные файлы и проверка
UID не защищают от процессов того же пользователя.

## Проверки

```sh
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
RTCH_IO_BACKEND=poll cargo test --locked
RTCH_IO_BACKEND=uring cargo test --locked
```

`cargo test` запускает и модульные, и интеграционные тесты. Нужны Bash,
стандартные утилиты Linux, Unix-сокеты и `/dev/ptmx`. Тесты используют
временные каталоги и завершают только собственные сессии.

Механизм I/O: `RTCH_IO_BACKEND=auto` (по умолчанию) ожидает события через io_uring
на Linux 5.11+ и переходит на `poll` при недоступности. `uring` требует io_uring;
`poll` включает совместимый режим. Чтение и запись остаются синхронными.
